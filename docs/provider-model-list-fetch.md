# 供应商模型列表获取与批量添加

## 背景

设置页「获取模型列表」从供应商 `GET /models` 拉取候选，用户勾选后批量添加。旧实现有两个问题：

- 模型列表请求读取 Provider Registry 的**可执行视图**。该视图只发布已启用且至少有一个可执行模型的供应商；新建供应商在尚未添加任何模型（或显式关闭启用）时不在其中，请求直接报“找不到该供应商配置”。
- 批量添加先 `reset()` 写入组件状态，再立刻 `commit()`。`reset()` 只调度 React 状态更新，`commit()` 仍闭包读取上一份草稿，导致所有勾选模型被判为无效而没有写入配置。

## 规则

1. **数据源**：模型列表请求读取 Provider 配置解析结果 `resolvedProviders`，其中包含未启用、零模型和隐藏供应商；不得使用只包含可执行模型的 Registry view。
2. **可用条件**：`access.type` 为 `api-key` 或 `zhipu-coding-plan-api-key`，且存在有效的 Base URL 与 API 格式。供应商的 `enabled` 状态和已添加模型数量不影响获取。
3. **错误展示**：供应商不存在、连接方式不支持、缺少 Base URL、鉴权失败、HTTP 错误和超时都在弹窗内展示，不静默失败。
4. **批量添加**：每个勾选模型都走与手动添加相同的推荐配置解析和保存链路。提交必须显式传入模型，不得依赖 `reset()` 之后尚未生效的 React 状态。
5. **幂等与冲突**：已在配置中的模型在弹窗内保持锁定勾选且不可取消；重复确认不会重复添加。
6. **状态所有权**：弹窗只持有勾选集合；`ProviderModelsSection` 负责逐个提交；Provider 配置层负责解析与持久化。

## 验收场景

1. 新建自定义供应商，已填写 API Key 与 Base URL，模型数为 0，`enabled` 未显式设置 → 「获取模型列表」可用，并展示远端模型。
2. 显式关闭 `enabled`、模型数为 0 的供应商 → 仍可获取模型列表。
3. 选中 2 个未添加模型并确认 → 两个模型都出现在供应商模型列表并完成持久化；重新打开弹窗后显示为已添加且不可取消。
4. 非 API Key 连接方式 → 获取按钮不可用；直接请求时返回统一错误。
5. 单个模型解析或保存失败 → 不阻断其他勾选模型的添加，失败项不写入配置。
